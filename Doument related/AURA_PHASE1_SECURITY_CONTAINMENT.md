No additional credential was identified by a limited keyword screen; that is not a comprehensive credential audit. All data is treated as private. No key value or decrypted record is recorded here.

## Root cause

Runtime artifacts were added to Git without ignore rules for `.keys`, SQLite memory, or Chroma persistence. Encryption provides no confidentiality against someone holding both the ciphertext and its key. Original runtime code generated missing keys automatically, which also risked stranding retained ciphertext if its key went missing.

## Changes made

- `.gitignore`: root-specific exclusions for `/.keys/`, `/.aura-private/`, `/aura_memory.db`, `/aura_memory.db-*` (SQLite sidecars), and `/aura_chroma/`. Source, examples, and unrelated databases are not broadly excluded.
- `core/key_management.py`: local Fernet key generation/loading, validation, exclusive key creation, missing-key protection when supplied memory paths exist, and a guard against an unfinished rotation.
- `core/memory.py`: uses that loader with its actual database paths. Existing encryption methods, database schema, and memory operations are otherwise unchanged.
- `test_key_management.py`: isolated fresh-install/reload, round-trip encryption, retained-data/missing-key, corrupt-key, and incomplete-rotation checks across four test cases.
- This report: evidence, recovery, and history-cleanup approval proposal.
- The seven runtime paths were removed from the Git index using `git rm --cached`; their local files were retained. The containment changes are intended for one ordinary local commit before requesting history-rewrite approval. No public push is included in this phase.

## Key status and local-first design

**The compromised active key has been replaced by a freshly generated Fernet key.** The new key remains only in ignored local `.keys/aura_aes.key`; its value has not been printed or committed. No cloud service or new configuration is required, so no secret-bearing template is needed. A fresh checkout generates its own local key and memory stores. A missing key alongside existing memory causes an explicit error instead of silent replacement; an invalid existing key is rejected unchanged.

Keep the project in a Windows account-private directory. Git ignore rules prevent ordinary accidental addition, not access by other local users or deliberate `git add -f`. Back up the key together with its corresponding private memory; do not copy either into a public artifact.

Untracking files alone does not break startup: SQLite and Chroma already create their stores when absent. The loader supports an empty fresh installation. Full AURA startup was not exercised here; unrelated dependencies and Ollama availability remain outside this phase.

## Data status and recovery

Before rotation, a byte-verified private backup was made at:

`D:\Project AURA\.aura-private\containment-20261010`

It contains the old `.keys/aura_aes.key`, original `aura_memory.db` (including pre-existing local modifications), and the entire original `aura_chroma/` tree. This backup intentionally contains compromised material and must remain private; never publish it.

Rotation occurred offline after process inspection found no running Python processes and no SQLite sidecars were present. It re-encrypted ten SQLite fields (three task/result pairs and four audit parameter payloads), plus the Chroma memory ciphertext and its queue duplicate. Every database table was compared before/after after normalizing decrypted fields: all values matched. Both SQLite integrity checks passed. The vector/index files were retained unchanged. Staged databases were vacuumed before replacement.

The initial replacement encountered a Windows file-sharing error; the recovery handler restored the originals. A fresh-process retry completed and was independently validated. The rotation marker has been removed. The one-time offline migration script is retained privately at `.aura-private/rotate_phase1.py`; it refuses to reuse an existing backup and is not a routine startup or re-runnable migration command.

Recovery, if ever needed: stop AURA, preserve any post-rotation data separately, then restore **the old key and both complete stores as one matched set** from that backup. Never restore just the key. Such rollback reactivates a compromised key and loses newer records unless those are migrated separately; use it only as temporary local recovery, then rotate again. No original data was discarded in this phase.

## Git-history status — approval required

**Public GitHub master still exposes the old key and databases. Local cleanup and rotation do not remove old commits or already obtained copies.** No destructive history rewrite or force push has been performed. Re-encryption protects future retained ciphertext under the new key; it cannot make historically published ciphertext secret again.

Removing historical key and memory paths is recommended because deleting current files alone leaves their contents available through Git history. The following is a proposal, not executed commands. It uses a separate private mirror and preserves this working checkout.

### Proposed actions and exact commands

Prerequisites: approve this operation, pause collaborator pushes, ensure the ordinary local containment commit exists, and ensure `git-filter-repo` version 2.47+ is installed. If the tool is missing, install it only as part of the approved cleanup environment. Recheck remote refs immediately before proceeding. Any unexpected branch/tag/remote change or newly discovered sensitive path requires revising the proposal before pushing.

```powershell
git clone --mirror https://github.com/Hunzala022/AURA.git 'D:\Project AURA\.aura-private\history-clean.git'
git -C 'D:\Project AURA\.aura-private\history-clean.git' fetch 'D:\Project AURA' master:refs/heads/master
git -C 'D:\Project AURA\.aura-private\history-clean.git' bundle create 'D:\Project AURA\.aura-private\pre-rewrite.bundle' --all
git -C 'D:\Project AURA\.aura-private\history-clean.git' bundle verify 'D:\Project AURA\.aura-private\pre-rewrite.bundle'
git -C 'D:\Project AURA\.aura-private\history-clean.git' remote remove origin
git -C 'D:\Project AURA\.aura-private\history-clean.git' filter-repo --sensitive-data-removal --invert-paths --path .keys/ --path aura_memory.db --path aura_chroma/
git -C 'D:\Project AURA\.aura-private\history-clean.git' log --all -- .keys/ aura_memory.db aura_chroma/
git -C 'D:\Project AURA\.aura-private\history-clean.git' show-ref
git ls-remote --heads --tags https://github.com/Hunzala022/AURA.git
```

The bundle and original checkout preserve recovery history privately. Removing the mirror's remote avoids an automatic ref refresh overwriting the imported local containment commit during filtering. Before any push, inspect filter-repo's changed-refs/commit-map, scan all resulting reachable objects for the removed paths and old key, rerun key tests in a clean checkout, and verify `main` still equals `f80eb20b382f26ab316aef4a31938e99f2159b10`. If main or other refs need changes, stop and expand the approval scope; do not leave affected public refs silently behind.

If only master needs updating, the proposed public mutation is:


This lease rejects a concurrent master update. Do not replace it with an unconditional force push if rejected. Known affected history starts at `7e898ba`, includes `257ef39`, `05047ed`, and the subsequent local containment commit; full changed-commit membership will come from the mirror's commit-map.
